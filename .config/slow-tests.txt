# The slow tier: tests that run whole programs, private buses and displays, wait on real time, or measure. CI runs
# it on every change; locally, `scripts/test --slow`. Every other test is in the fast tier, which scripts/test holds
# to 2 seconds a test and 5 minutes for the workspace. A test belongs here only when it cannot be made fast: say why
# in the comments below.
#
# One test per line: the nextest binary id, a space, then a filter on test names (`test(=module::exact_name)`,
# `test(/regex/)`), or `all()` for the whole binary. Keep the lines sorted. `ci/test_suite.py --write` writes both
# tiers' filters in .config/nextest.toml from this list, and `ci/test_suite.py --check` fails when they differ. Git
# merges this file by keeping both sides' lines, so branches that each add a test do not conflict.
#
# Why the tests below are slow:
# The real Files' quick previews over their window start the server and Files and open a preview, one waiting for it
# to shrink away: about 2.2 s each.
# The compositor's dither and coverage drawn on the GL path against their definitions (`dither::`, `coverage_gl::`)
# make a GL context and compile programs like the other shader-against-model tests here.
# Tests that start the whole shell or several real client processes and draw whole outputs (app grid, dock menus,
# lock screen, scene repaints, minimize meshes, output seams), or walk the whole source tree, take 2 to 3.5 s on an idle
# machine, past the fast tier's budget.
# The GPU slice's sessions run its client process for 60 to 240 frames at the display's real refresh (1 to 4 s each).
# The server's tests of the toolkit's programs made at its start make a GLES context, compile programs and run the
# presenter's check window for 90 frames.
# The GPU layer's device tests (cupertino-gpu's suite and its borrowed-context test) each make one or more GLES contexts
# and compile programs: about 0.2 s alone, past a second when the driver makes many at once.
# The live resizes of the real Settings and Files windows on the GPU at 3840 x 2160 and scale 1.5 start a program, warm
# its device up and resize it for about 3.5 s.
# Whole-window pixel comparisons at several scales (kit damage_coverage, control_fixtures::alert, files kit_damage idle
# window) and the control panel moving between outputs, which starts the real shell process again, take 3 to 8 s.
# The shell processes with no output start eight real shell processes, start each again with the display gone and
# measure what they do over two seconds of real time: about 2.5 s.
# The notifications process with no output passes a second of real time around a display unplugged and plugged in:
# about 1.5 s alone.
# The login screen of the greeter session runs as a real process under a mouse moving for a second of real time, is
# kept busy for that second, waits out a display sleep and a password refused, or is started a second time: 3 to 9 s.
# The notification list closing at a press on either output, at Escape and at the control panel opening starts two
# real shell processes and opens the list four times: about 2.2 s.
# The full notification list drawn at 2x in four appearances on the CPU takes about 1.5 s alone, more beside the
# workspace's tests.
# The dock's open stack placed at two more scales, at each edge, with and without magnification and for two sizes of
# folder runs the dock some forty times (about 6 s), and its grid drawn at 2x in eight appearances on the CPU takes
# about 2 s.
# The app effects protocol's glass style tests, the sidebar fades, the shadow at the start of a fade (three servers,
# 2 s alone), every frame of a fade over two windows, a late backdrop tone, a server panic's end, the sidebar line
# over popup glass and the screen share each start the server and draw several frames: 2 to 3.3 s with the
# workspace's tests beside them.
