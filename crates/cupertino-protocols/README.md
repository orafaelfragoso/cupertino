# cupertino-protocols

The private Wayland protocols between the Cupertino server and its shell processes, with generated bindings:
`protocols/cupertino-shell-v1.xml`, `protocols/cupertino-screenshot-v1.xml`, `protocols/cupertino-control-v1.xml`, `protocols/cupertino-global-shortcuts-v1.xml`, `protocols/cupertino-host-v1.xml`, `protocols/cupertino-transaction-v1.xml` and `protocols/cupertino-overview-v1.xml` (modules `host`, `transaction` and `overview`, not used yet). The public protocols any client may bind
live in `cupertino-app-protocols` (MPL-2.0); `client::{app_effects, scroll}` and `server::{app_effects, scroll}` re-export
them, so the server names every protocol through this crate. Depends on `cupertino-app-protocols`.

**Why the roles stay in `cupertino_shell_v1`.** The private interfaces keep their per-role objects (menu bar, dock, window
manager, session) under one factory instead of a new `cupertino_shell_control_v1`: the objects already separate the
roles, a rename would change every shell process's wire code without adding a check, and the server's authorisation does
not live in the interface name but in the connection (`cupertino-server`, `authorization.rs`). What changed is that the
global is hidden from every connection without a shell role, each `get_*` and each request on a role object checks the
role again, and what applications use moved out to a public protocol of its own.

## Public API

| Interface | Role |
|---|---|
| `cupertino_control_v1` | private desktop control, offered only to DesktopControl; it grants no shell, capture or prompt role. Version 1 is discovery: an inactive session, fresh run epochs, status queries and stale-epoch refusals. Version 2 adds output-scoped consent, input and capture, version 3 semantic observation and actions, version 4 the app each run comes from (`identify`). Version 5 allows eight live sessions on one connection, one run per agent the controller serves, each with its own held input, and `select_capture`, which makes the next output capture source the selecting run's |
| `cupertino_global_shortcuts_v1` | the chords of the portal's global shortcuts, offered only to the portal process (`ShellRole::GlobalShortcuts`): the server sends the chords it keeps for itself (`reserved` … `done`, again when its bindings change); `bind(id, modifiers, keysym)` and `unbind(id)` route a chord to the object where no binding of the server takes it, and `pressed` and `released` report its key going down and up, the focused client getting neither. Every chord goes with the object |
| `cupertino_shell_v1` | the private role factory (version 31; version 31 removes the `agent_trust` enum and the `session_agent` event from the menu bar, which takes the session menu's state from the session agent component, and leaves a menu bar bound below 31 inert; version 30 adds `get_keyboard_panels`; version 29 removes the `strip` placement, the rectangle of `set_placement` and the `strip_pressed` event from the window manager, whose strip is its own layer surface with holes, and leaves a window manager bound below 29 inert; version 28 removes the overview's `overview_window`, `overview_workspace`, `overview_changed` and `overview_closed` events, the `overview_mode` enum, the `overview_frame`, `overview_select`, `overview_close`, `overview_drag`, `overview_move_window` and `overview_workspace_frame` requests and the `window_thumbnail` event from the dock, which the overview component (`cupertino_overview_v1`) and its holes replace, and sends `gesture` only for a gesture no transaction is bound to; version 26 adds `activate_window` (one window of a tile's menu shown: restored, raised and focused) to the dock; version 25 adds `active_client_keys` (the class of the active window's keys, after `active_client`) to the menu bar; version 24 adds `active_client` (the process behind the active window and its kind) to the menu bar; version 23 adds `overview_drag`, `overview_move_window` and `overview_workspace_frame` to the dock; version 22 adds `window_thumbnail` to the dock; version 21 adds `backdrop_bands` to the menu bar; version 20 adds `activate_app` and `app_activation` to the session object; version 19 adds `app_resident` to the dock; version 18 adds `engage` to the dock; version 17 adds `window_icon` to the dock; version 16 adds `window_full_screen` to the menu bar; version 15 adds `window_controls` to the menu bar; version 14 adds `backdrop_luminance` to the menu bar; version 13 adds `force_quit_app` to the menu bar; version 12 adds `engage_help` and the `help_search` bound action to the menu bar; version 11 adds `edit` to the menu bar; version 10 adds the window list, the bound chords and window commands 7–15 to the menu bar; version 9 adds `log_out_requested` to the session object; version 8 adds `session_agent` to the menu bar; version 7 adds `lock_requested` to the session object; version 6 adds `session_action` to the menu bar), offered only to the processes the server started for a shell role: `get_menu_bar`, `get_dock`, `get_session` and `get_window_manager` hand out the objects below. Each request needs the role it creates (`ShellRole` in `cupertino-server`); a connection that lacks it gets the error `permission` and an inert object. Version 5 removed `get_backdrop` and `set_titlebar_style`, which moved to the public `cupertino_app_effects_v1` |
| `cupertino_menu_bar_v1` | the menu-bar role of a layer surface: active application and menu feed, `set_menu_open`, `window_command`, `move_to_workspace`; from version 4 `session_action` (an entry of the session menu: sleep, restart, shut down, lock, log out, switch user, refresh capabilities; the server forwards it to the session agent, which answers only the server; an unknown value is the error `invalid_session_action`); from version 3 `screen_capture` (a capture session runs); from shell version 10 the window list (`app_window`, titles cut to 1024 bytes) and `activate_window` (resolved when it arrives, ignored while the session is locked), the bound chords (`shortcut`, `primary_modifier`) and the `window_command` entries 7–15 (full screen, tiling, bring all to front, cascade, minimize all, zoom all, force quit dialog); from shell version 11 `edit` (undo, redo, cut, copy, paste, select all: taken only while this bar's popup grab is active, sent once to the key window on the first keyboard focus change after the grab ends if it lands there within 500 ms, every guard checked again before sending; a terminal gets only copy and paste as Shift+Ctrl, a first-party or opted-out client the profile's primary modifier, any other Ctrl; never an X11 window, a lock, layer or shell surface, nor during a lock, the overview, the switcher or another grab; an unknown value is the error `invalid_edit_action`); from shell version 12 the event `engage_help` (the Help search shortcut: open the Help menu with its search field focused, taking the keyboard as for `engage`; sent in a group of its own to the bar of the active output, never while the session is locked or a lock is pending) and the `bound_action` entry `help_search`, whose chord comes in the shortcut group; from shell version 13 `force_quit_app(app_id)` (the Alt alternate of Force Quit: the server force-quits the active application as the dock's `force_quit_app` does, only if `app_id` equals the active application's id when it handles the request; any other id, an id over 255 bytes, and every request while the session is locked or a lock is pending is ignored without an error); from shell version 14 to 20 the event `backdrop_luminance` (the perceptual lightness, CIE L*/100 in thousandths, of the mean colour of the output's wallpaper under the bar's strip, in a group of its own after the first groups and again when it moves by more than 10; from shell version 21 the event `backdrop_bands` in its place, the mean encoded sRGB colour of that wallpaper in bands of equal width across the output, three little-endian 16-bit channels from 0 to 65535 per band, at most 256 bands, in a group of its own and again whenever a band changes, from which the bar takes the relative luminance under the whole strip or under one item; nothing is sent without a measure, a sent measure is never withdrawn, and nothing of a window or another client is sampled); from shell version 15 the event `window_controls` (the `window_control` bitfield of the active window's enabled controls, minimize and zoom, in every group that has `window_state`; `can_zoom` keeps meaning zoom is enabled for older bars, and a bar that was not sent it keeps both enabled. The server sends it from the controls `cupertino_app_effects_v1.set_disabled_controls` disabled and the window's size limits); from shell version 16 the event `window_full_screen` (1 while the active window is in full screen, 0 otherwise, in every group that has `window_state`; a window in full screen can always be taken out of it, so a bar offers leaving even where zoom is disabled) |
| `cupertino_dock_v1` | the dock role: window feed, `activate_app`, `restore_window`, `set_minimize_target`; the `toggle_app_grid` event (the dock opens or closes its application grid); from shell version 4 the `unresponsive` and `force_quit_dialog` events and the `force_quit_app` request; the application switcher's `switcher_output`, `switcher_entry`, `switcher_changed` and `switcher_closed` events and the `switcher_select`, `switcher_activate` and `switcher_cancel` requests; the `attention` event for a refused activation; the `switch_workspace`, `add_workspace`, `remove_workspace` and `move_workspace` requests; the `hot_corner` and `gesture` events (a gesture no transaction is bound to) with the `run_action` request; `app_command` for the tile menus; from shell version 17 the `window_icon` event (the icon a window set with `xdg_toplevel_icon_v1`, copied by the server when the window committed it: a theme name, refused when over 255 bytes or holding `/`, `..` or NUL, and the largest square image of at most 512 pixels a side as a sealed ARGB8888 file); from shell version 18 the `engage` event (the Focus Dock shortcut: the bar takes the keyboard); from shell version 19 the `app_resident` event (an application whose process is connected after showing a window, with or without windows now, and when it stops being so); from shell version 26 the `activate_window` request; from shell version 28 none of the overview's messages and no `window_thumbnail` (versions 22 and 23 had them) |
| `cupertino_session_v1` | the session observer of the shell processes with the Session role (`lock_requested(explicit)` from shell version 7, sent only to the connection that also holds the session lock role, the server's private way to ask the lock screen to lock; `log_out_requested` from shell version 9, the same way for the log out confirmation; the appearance observer plus the lock state): `appearance` (dark or light), `display_options` (version 2: the `display_option` bitfield of reduce motion, reduce transparency, increase contrast and differentiate without colour) and `locked` / `unlocked`, sent on creation and on every change; from shell version 20 the `activate_app(serial, desktop_id)` request (the launcher opening an application: the server brings an application that shows a window forward as the dock's `activate_app` does and answers `app_activation(serial, result)` with `activated`, `resident` or `not_running`; it starts nothing, and the Session role is checked on every request). an object the shell global creates has the version the global was bound at, and the `since` of each of its messages is the shell version that added it (the server sends nothing newer than that) |
| `cupertino_window_manager_v1` | the window manager of an output (`get_window_manager`, the role takes no surface; the strip is the window manager's own layer surface, its thumbnails claimed holes): the usable area and the arranged windows, `toggle_stage`; `set_placement` (stage or hidden) applied together on `commit`, `activate_window`. The server fades hidden windows and puts every window back when the object goes away; it draws no strip |

## How it works

The crate generates bindings from its protocol XML. `build.rs` reruns when the XML changes, because the scanner macros read it untracked.

| Feature | Generates |
|---|---|
| `client` | `cupertino_protocols::client`, used by `cupertino-shell-client` and `cupertino-screenshot` |
| `server` | `cupertino_protocols::server`, used by `cupertino-server` |
