# Check a release candidate on hardware

An rc passes when hosted CI is green for its exact commit and a maintainer's machine passes this checklist on a real TTY. A nested or headless run does not replace the hardware checks. Record each result as **pass**, **fail**, or **blocked**, with the observed result. An unchecked or blocked item does not pass. Record the lid check as **N/A** on a desktop. Link any exception to the maintainers' explicit release decision.

Use the same candidate for the checkout and installed Arch packages. Have a working Wayland terminal available. Use disposable files, save other work before quitting, and record settings before changing them so you can restore them afterward. `Super` means the keyboard's primary desktop modifier.

## Scope of this gate

This checklist predates several merged features. The [roadmap](roadmap.md) records the current phase assessment. Run the checks against one exact candidate; an old issue title is not evidence that a feature is still missing.

Browser portals, polkit, PipeWire controls, output configuration, multi-GPU handling, explicit sync and pointer constraints now have implementations. Their presence does not establish hardware acceptance. Credential storage through gnome-keyring is implemented too ([#117](https://github.com/orafaelfragoso/cupertino/issues/117)). The installed-session check of the portals, polkit and credential services is still open in [#23](https://github.com/orafaelfragoso/cupertino/issues/23). External input methods and remaining interface restrictions stay open in [#24](https://github.com/orafaelfragoso/cupertino/issues/24) and [#28](https://github.com/orafaelfragoso/cupertino/issues/28).

The detailed steps below also cover historical package and checkout paths. Record the service backend actually shipped by the candidate: the ISO uses NetworkManager and BlueZ, with Settings adapters. Record multi-monitor and GPU results against the implemented behaviour in [Displays and GPUs](displays-and-gpus.md), rather than the original missing-feature descriptions in #22 and #27.

## Run the checks

Run the checks in order. Keep the original text-console login open for the final log collection.

1. Record the candidate and hosted CI result. From the candidate checkout on a text console, run:

   ```sh
   report=$(mktemp -d "$HOME/cupertino-rc.XXXXXX")
   started=$(date --iso-8601=seconds)
   git rev-parse HEAD > "$report/commit.txt"
   uname -a > "$report/kernel.txt"
   df -h /home > "$report/disk.txt"
   tty > "$report/source-vt.txt"
   lspci -k > "$report/hardware.txt"
   pacman -Q cupertino cupertino-data cupertino-kit > "$report/packages.txt"
   printf 'Report directory: %s\n' "$report"
   ```

   Open the candidate's commit on GitHub and record the hosted CI run URL in the report. Expected: every required CI job succeeds for that SHA, the installed packages come from the same candidate, and `/home` has at least 30 GB free before the source build. A green run for an earlier commit does not pass. Guards [#13](https://github.com/orafaelfragoso/cupertino/issues/13) and [#14](https://github.com/orafaelfragoso/cupertino/issues/14).

2. Start the checkout from the logged-in text console with `./run-cupertino.sh`. Expected: the compositor takes the display and shows the dock, menu bar, Files, and Settings. Both windows accept input. The script prints `~/cupertino-tty.log`; a build failure or a blank desktop fails this check. Record display resolution, refresh rate, and scale. Guards [#9](https://github.com/orafaelfragoso/cupertino/issues/9).

3. Switch to a spare console with `Ctrl+Alt+F4`, log in as the same user, and run `ps -u "$USER" -o pid=,args= | grep '[c]upertino-'`. Return to the source VT recorded in step 1. Expected: `cupertino-server` and the nine shell processes of the packaged configuration, `cupertino-dock`, `cupertino-menubar`, `cupertino-launcher`, `cupertino-notifications`, `cupertino-controlcenter`, `cupertino-osd`, `cupertino-files --desktop`, `cupertino-windowmanager`, and `cupertino-login`, are present for this session. Files and Settings are also present. The server also starts its four built-in processes, `cupertino-portal`, `cupertino-polkit-agent`, `cupertino-keyring-prompter` and `cupertino-control`, from the installed package, never from the checkout; `cupertino shell list` shows them as `portal`, `polkit-agent`, `keyring-prompter` and `desktop-control`. Repeated process exits or restarts fail. Guards [#17](https://github.com/orafaelfragoso/cupertino/issues/17).

4. Move the mouse slowly onto a window-close button without clicking it, then move quickly across the display and back. Expected: small corrections remain controllable, fast motion covers useful distance, and the pointer does not jump or drift after the mouse stops. Record the mouse model, hardware DPI, and display scale. Guards [#1](https://github.com/orafaelfragoso/cupertino/issues/1).

5. Open **Settings > Mouse**. Set **Mouse resolution** to the mouse's known hardware DPI, using the named device row when more than one mouse is attached. Compare a fixed physical movement at two known hardware DPI settings, with the matching resolution selected each time. Expected: matching DPI preserves comparable pointer travel and the selected resolution remains visible after leaving and reopening the pane. If the hardware DPI cannot be established, record this comparison as blocked. Guards [#1](https://github.com/orafaelfragoso/cupertino/issues/1).

6. In **Mouse**, move **Tracking speed** to a lower stop, then a higher stop. Toggle **Pointer acceleration** off and on. Restore the original values. Expected: speed changes immediately; with acceleration off, equal physical distances give comparable pointer travel at slow and fast speeds. With acceleration on, fast movement travels farther without losing slow precision. Guards [#1](https://github.com/orafaelfragoso/cupertino/issues/1).

7. Open a Files folder with enough entries to scroll, then scroll the Accessibility pane in Settings. Turn the wheel one notch at a time. Expected: a notch moves a useful amount, about three text lines where applicable; both apps scroll consistently and stop when input stops. Guards [#2](https://github.com/orafaelfragoso/cupertino/issues/2).

8. In **Mouse**, turn **Natural scrolling** off, scroll Files, then turn it on and repeat the same wheel movement. Restore the original value. Expected: direction reverses immediately without restarting either app. If a trackpad is available, repeat with its **Natural scrolling** control and a two-finger gesture; record the trackpad result separately. Guards [#3](https://github.com/orafaelfragoso/cupertino/issues/3).

9. Record the current `input_sources` entry in `~/.config/cupertino/keyboard.conf`. Set only that entry to `input_sources = us, de`. Focus Settings search and use `Ctrl+Space` to switch sources. Press the physical key immediately right of **T** in each source. Expected: the input-source switcher HUD changes its selected source, the key produces `y` in US and `z` in German, and switching requires no app restart. Restore the original entry after checking both sources.

10. Press `Super+Space`, type `settings`, and press Escape twice. Hold `Super+Tab`, select Files, and release Super. Press `Super+W` to close that Files window, then reopen Files from the dock. Expected: the launcher receives the text, the first Escape clears the query, and the second Escape closes it; the switcher activates the chosen app on release; the close shortcut affects only the focused window.

11. In Settings search, type `alpha beta`. Press `Super+A`, type `gamma`, move the caret with Left and Right, then click between two characters and type `X`. Repeat selection and replacement in the launcher and the Files rename editor. Expected: the caret is visible, the selected range is highlighted, typing replaces the selection, and clicks place the caret at the clicked character boundary. Cancel the rename. Guards [#4](https://github.com/orafaelfragoso/cupertino/issues/4) and [#16](https://github.com/orafaelfragoso/cupertino/issues/16).

12. Open **Settings > Accessibility > Colour filter**. Click the Appearance sidebar row once while the menu is open. Expected: the menu closes, the selected filter stays unchanged, and the pane remains Accessibility. A second click opens Appearance. Return to Accessibility and reopen Colour filter. Press Escape to close the menu, then change pane with `Super+[` or `Super+]` where history is available, or click a sidebar row. Expected: Escape closes the menu and the pane change leaves no popup from the previous pane. Do not expect history shortcuts to navigate while the menu is open. Guards [#5](https://github.com/orafaelfragoso/cupertino/issues/5).

13. Reopen **Colour filter**. Use Down and Up, type the beginning of an item name, and press Escape. Reopen it and select an item with Return, then restore the original value. Expected: highlighting follows the keys, typing selects a matching item, Escape cancels, Return chooses, and the pane beneath receives none of those keys. Guards [#18](https://github.com/orafaelfragoso/cupertino/issues/18).

14. In a terminal opened with `Super+Return`, run `mktemp -d "$HOME/cupertino-files-rc.XXXXXX"` and record the printed path. Open that empty folder in Files. Create a folder, rename it to `rc-renamed`, open it, and go back. Expected: names and location update immediately, back navigation returns to the parent, and the selection remains visible. Use only these disposable items.

15. Focus Files, then Settings, by clicking their windows. Open each app's name menu and its **Window** menu. Expected: the menu bar identifies the focused app, each opened menu responds, and dismissal returns keyboard input to that app. Record missing app-specific commands against [#6](https://github.com/orafaelfragoso/cupertino/issues/6); do not treat a visible label as proof that a command works.

16. Open **Settings > Wi-Fi**, then **Bluetooth**. Expected: Wi-Fi says "Wi-Fi is not available" when neither NetworkManager nor `cupertino-netd` is running. Bluetooth says "Bluetooth is not available" when neither BlueZ nor `cupertino-btd` is running. On the ISO, NetworkManager and BlueZ provide these services through Settings adapters. If neither backend is available, the unavailable message passes only this UI check; record connecting and pairing as blocked. Then search for `natural scrolling`, choose the Mouse result, change the setting, leave the pane, and return. Restore the value. Expected: the result reaches Mouse, the wheel direction in Files matches the new setting, and navigation leaves no search popup. Raw bus errors, a frozen control, or a value that silently resets fail. Guards [#3](https://github.com/orafaelfragoso/cupertino/issues/3) and [#5](https://github.com/orafaelfragoso/cupertino/issues/5).

17. Place Files and Settings side by side. Change **Settings > Appearance** from Light to Dark and back. Repeat after opening a Colour filter popup. Expected: both apps, the menu bar, and dock update live; Files and Settings share the content-background treatment in each appearance; text remains readable; no old popup survives. Guards [#8](https://github.com/orafaelfragoso/cupertino/issues/8) and [#5](https://github.com/orafaelfragoso/cupertino/issues/5).

18. Open **Settings > Wallpaper** and choose a picture under **Pictures**. Expected: the desktop picture changes without restarting the session. Prepare a disposable folder with two different permitted JPEGs named `rc.jpg` and `rc-dark.jpg`. Click **Add Folder…**, navigate to that folder in the chooser, and click **Choose**. Select its paired thumbnail. Switch **Appearance** to Dark, then Light. Expected: the folder and thumbnails appear, selecting the pair changes the desktop live, and each appearance switch immediately shows its corresponding image. The pair's preview says "Light and dark: follows the appearance."

   Click **Add Photo…**, choose a different permitted JPEG, and click **Add**. Expected: the chooser closes and the chosen single picture appears live in both appearances. Select the folder's pair again, then click **Remove** beneath that folder. Expected: its section disappears immediately, without deleting the files or changing the active picture. Removing a folder only removes its source listing. Choose a pack picture again and confirm that the desktop changes live; restore the original picture and appearance. On failure attach `source-tty.log` or the packaged `user-journal.log` from check 29, the selected filenames, appearance, and action time. Guards [#7](https://github.com/orafaelfragoso/cupertino/issues/7).

19. Drag a window by its title bar and resize it from a corner. Release the mouse, then move the pointer away. Expected: the window follows while held, stops on release, and the pointer remains free. Typing after focusing the other app reaches that app. This checks ordinary held-button dragging only. Request validation, focus protection and hung-app detection have separate tests; this step does not exercise every case in [#20](https://github.com/orafaelfragoso/cupertino/issues/20).

20. Press `Super+Ctrl+Q`. Try typing and clicking before unlocking, then enter one incorrect password followed by the correct password. Expected: the lock screen covers the desktop, input never reaches the apps, the incorrect password keeps the lock, and the correct password restores the same windows and usable input. Guards [#17](https://github.com/orafaelfragoso/cupertino/issues/17).

   Lock again and enter two incorrect passwords. Switch to the spare text console with `Ctrl+Alt+F4`, log in as the same user and run `faillock --user "$USER"`. Expected: two failures from the lock screen are listed (the lock screen counts towards the account lockout). Switch back and unlock with the correct password; afterwards `faillock --user "$USER"` lists none.

21. Switch to the spare text console with `Ctrl+Alt+F4` and back to the recorded source VT. Repeat once while locked, then unlock. Expected: the console and desktop both redraw, the pointer and keyboard work after each return, and a locked session stays locked. Black output, stale frames, or lost input fail. Guards [#9](https://github.com/orafaelfragoso/cupertino/issues/9).

22. Leave Files and Settings open. In a terminal inside the desktop, note the time with `date --iso-8601=seconds`, then run `systemctl suspend`. Wake the machine with its power button or supported wake key, then unlock. Expected: logind's sleep notification locks the session before sleep; on wake the display redraws and the same apps accept pointer and keyboard input after authentication. On wake the server treats the end of sleep as input and wakes the displays. A crash, persistent black display, or lost input fails. If logind refuses suspend, record its reason as blocked, not a successful resume. On failure attach `source-tty.log`, `power-journal.log`, and `kernel-journal.log` collected in check 29; for the packaged repeat, also attach `user-journal.log` and `login-journal.log`. Include the sleep and wake times. Guards the session-reactivation path also exercised by [#9](https://github.com/orafaelfragoso/cupertino/issues/9).

23. On a laptop, leave Files and Settings open and record whether it is on AC power, docked, or driving an external display. Record the host's lid policy with `systemd-analyze cat-config systemd/logind.conf`. Close the lid, then reopen it; wake and unlock if it suspended. Expected: the host's logind policy decides whether closing the lid suspends. Cupertino does not set a separate lid action. If the host suspends, the lock and resume expectations in check 22 apply. If it does not, reopening leaves the desktop and input usable without requiring a suspend event. Mark this check **N/A** on a desktop. On failure attach the check-22 logs, lid policy, power/dock state, and close/open times. Display rearrangement caused by closing a laptop panel retains the known limitations of [#22](https://github.com/orafaelfragoso/cupertino/issues/22).

24. With Files and Settings open, record the external display's connector and unplug time. If another display remains active, put a normal, unminimized window on the external display first. Unplug its video cable, verify the remaining desktop, then reconnect the same cable and test pointer and keyboard input again. Expected on the selected GPU: the disconnected head disappears; with an output remaining, normal windows from the removed output move into the first remaining output's current workspace and fit its usable area. Reconnection announces the head again and enables it unless its stored configuration disables it, using its stored settings or the default preferred mode. A compositor crash or lost input on the remaining display fails. Record these known limitations without failing this gate: restoration of original positions and workspaces, mixed-scale transitions and last-output reconnection require explicit observed results ([#22](https://github.com/orafaelfragoso/cupertino/issues/22)); connectors on a second GPU are implemented but still need hardware verification ([#27](https://github.com/orafaelfragoso/cupertino/issues/27)). If the external display is the only output, still unplug and reconnect it, but classify stranded-window behavior against #22 rather than expecting automatic recovery. If no external display is available, mark this check blocked. On failure attach `source-tty.log` or the packaged-session logs, plus `kernel-journal.log` from check 29. Include the connector, remaining outputs, plug times, and any `display disconnected`, DRM, or connector-scan messages.

25. Save any work and press `Ctrl+Alt+Backspace` to end the checkout run. On the original console, run `cp "$HOME/cupertino-tty.log" "$report/source-tty.log"`. Expected: the script returns to that console without a crash, and the compositor and its shell children have exited. Check with the process command from step 3. This shortcut tests compositor exit, not a confirmed user logout.

26. Return to the machine's existing display manager, choose its **Cupertino** session, and log in. Do not enable or replace a display manager for this check. Expected: the packaged session entry starts `/usr/bin/cupertino-session` and reaches the desktop without `run-cupertino.sh` or a checkout on `PATH`. Open Files and Settings from the dock or launcher. If there is no configured session chooser, mark this check blocked rather than substituting the checkout script. Guards [#13](https://github.com/orafaelfragoso/cupertino/issues/13) and [#17](https://github.com/orafaelfragoso/cupertino/issues/17).

27. In the packaged session, repeat the process inventory from step 3, the launcher and switcher actions from step 10, the wallpaper actions from check 18, and lock, unlock, VT return, suspend, lid, and monitor hotplug from checks 20–24. Record each result separately, preserving the desktop lid N/A and the documented display limitations. Expected: all nine packaged shell processes and the four built-in processes run (`cupertino shell list`), their executable paths resolve to installed binaries, and the desktop remains usable after unlock and VT return. Do not accept the checkout run as evidence for this path. Guards [#17](https://github.com/orafaelfragoso/cupertino/issues/17) and [#9](https://github.com/orafaelfragoso/cupertino/issues/9).

28. Save work in the packaged session and press `Ctrl+Alt+Backspace`. Expected: the compositor and its shell processes exit, the display-manager session ends, and its login screen returns. Verify from the spare console with the process command in step 3. This tests compositor exit, not a confirmed log out. Then log in again and choose Log Out from the menu bar's system menu (or `Super+Shift+Q`) and confirm: the applications are asked to quit and the login screen returns. Record the session menu against [#19](https://github.com/orafaelfragoso/cupertino/issues/19).

29. On the original text console, collect the packaged-session and login-manager journal since the recorded start time:

   ```sh
   sudo journalctl -b --since "$started" _UID="$(id -u)" > "$report/user-journal.log"
   sudo journalctl -b --since "$started" \
     -u display-manager.service > "$report/login-journal.log"
   sudo journalctl -b --since "$started" \
     -u systemd-suspend.service -u systemd-logind.service > "$report/power-journal.log"
   sudo journalctl -b --since "$started" -k > "$report/kernel-journal.log"
   ```

   Expected: the report contains the exact SHA, hosted CI URL, package versions, hardware details, per-check results, and `source-tty.log`. For each failure, attach the relevant log and include its check number, timestamp, expected result, observed result, and reproducible action. If the display manager redirects session stderr to a file instead of the journal, attach that configured file too; an empty journal is not proof of a clean run. Include both startup warnings from [#9](https://github.com/orafaelfragoso/cupertino/issues/9) if present. Review logs for private data before sharing. Restore the recorded input and appearance settings. Record who ran the gate and the date; leave unexecuted checks marked blocked.
